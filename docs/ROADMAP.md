## 1. 「100%」の定義

次の 4 つがそろったら、そのタイトルは 100% とする。

1. **自分のロードマップ／憲章のスコープが終わっている**（残りは「v1.0 のあと」に明示的に移す）
2. **UI/UX が共通の基準（3 章）を満たす**
3. **ドキュメントがコードと食い違っていない**（SPEC の状態・README・ヘルプの文言）
4. **v1.0 として版を切る**（版の番号・変更履歴）

## 3. UI/UX の共通の基準（DeckBattle・10 buy year から）

各タイトルは、この表で足りないものを SPEC にして埋める。キャンバス描画のタイトル（Fortress）は、意味の合うものだけを当てはめる。

| 分類 | 基準 |
|---|---|
| 画面の器 | `viewport-fit=cover`。高さは `100dvh`（`100vh` は予備）。ページ自体はスクロールさせない（`overscroll-behavior:none`） |
| | 画面の端に貼り付くもの（ヘッダー・フッター・トースト・モーダル）は `max(Npx, env(safe-area-inset-*))` で逃がす |
| | 360×640・375×667・390×844・412×915・PC で崩れない。背の低い画面は `max-height` の分岐で詰める |
| トークン | 色・アクセント・良し悪し・角の丸み・影・フォント・イージングを `:root` に置く。部品の中に色を直書きしない |
| | Google Fonts を `preconnect` ＋ `display=swap` で。見出し・数字・本文でフォントを分ける。`theme-color` を付ける |
| 部品 | ボタンは押した感じ（縮む・沈む）と `:disabled` の見た目を持つ。`touch-action:manipulation`・タップのハイライトを消す |
| | モーダルは 1 つの仕組みで。`role="dialog"`・`aria-modal`・Esc で閉じる。`alert()` を使わない |
| | トーストは safe-area の内側に出し、`aria-live` で読み上げ、勝手に消える |
| 演出 | 画面の切り替えに動きを付ける（0.6 秒以内） |
| | 当たり・報酬に手ごたえ（揺れ・粒子・数字のポップ・カウントアップ） |
| | 演出は遊びを止めない（0.8 秒以内・タップで飛ばせる・同時に出す数に上限） |
| | `prefers-reduced-motion` を CSS と JS（キャンバスの揺れ・待ち時間）の両方で守る |
| 音 | 最初の操作のあとにだけ鳴らす。ミュート（できれば BGM と SE を別々）を保存する。SE は鳴らしすぎない |
| 画面の流れ | タイトル → 遊ぶ → 結果（段階的に見せる）→ もう一度。ヘルプ・遊び方がいまの内容と合っている |
| | 初めての人が迷わない導入（手順を絞る・指差し） |
| 外向き | OGP と Twitter カード（1200×630）、`manifest.json`、apple-touch-icon、ファビコンがそのタイトルのもの |
| 共通基盤 | SDK を `defer` で読み、失敗しても遊べる。スコアの計算は純関数でテストを書く |
| テスト | `node --test`（またはそのリポジトリの道具）でロジックのテスト。CI で回す |
