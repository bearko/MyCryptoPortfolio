## 1. 背景（作者の依頼 2026-10-18）

bearko.games に初めて来た人は、遊べるゲームが多いので **何から手を付ければいいか・どれが自分に合うか** が分からない。そこで、サイト全体の分かりやすい目標を 1 つ置く。

- **アチーブメント**（今のトロフィー）を「ヒーロー」と「エクステンション」に分ける
- **ヒーローは名鑑に集める札（コンプリートの対象）** にする。ゲームクリアなどの **節目** で手に入るものは、すべてヒーローにそろえる
- **ヒーロー名鑑をすべて埋めたら、真のゲームクリア**
- **エクステンションは、初めての来訪など軽い目標** で手に入れる。全部を集めることを条件にしたヒーローも 1 枚置く
- **レアリティはマイクリ原作のもの** を使い、達成の難しさに合ったレアリティのヒーロー／エクステンションを選ぶ。額縁などの見た目もレアリティで変え、レアリティを札に書く
- ナビゲーターの **マイン** が、遊ぶ → 戻る → アチーブメントの順に、**段階を分けて** 案内する（一度にたくさん説明しない）

## 2. 考え方

### 2.1 2 種類のアチーブメント

| | ヒーロー（名鑑） | エクステンション |
|---|---|---|
| 役割 | コンプリートの対象。全部で「真のゲームクリア」 | 寄り道の記念。遊び方を広げるきっかけ |
| 手に入る場面 | **節目**：最初の節目・中盤の節目・ゲームクリア・やり込み・タイトル横断の大目標 | **軽い目標**：各タイトルを遊ぶ（来訪）・タイトル内の小さな目標・共通基盤の機能（ログイン・アイコン・チャット・RTA・マインの話） |
| 数 | **100 枚**（8 タイトル × 11 ＋ 横断 12。作者の決定） | 39 個（8 タイトル × 4 ＋ 共通基盤 7） |
| レアリティ | 難しさに合わせて Common〜Legendary（2.3） | **すべて Epic 以上**（来訪も含む。作者の決定）。軽いものは Epic、大きめは Legendary |
| 見た目 | アーチの額縁に飾る。未獲得は影絵 | 四角い台座に飾る。未獲得は影絵 |
| ほかの使い道 | アイコン図鑑（SPEC-006） | アイコン図鑑。開発中の TCG でカードとして使え、有利になる予定（TCG の SPEC で決める） |

- **Rare 以下のエクステンションは、TCG の中でだけ手に入るアチーブメント**にする（アチーブメントをカードにして戦うゲームの想定。作者の決定）。bearko.games のアチーブメントには入れない

- 種類は **アイコンの絵（`hero:` / `ext:`）で決まる**。トロフィーの定義に別の欄は持たない（食い違わないように）
- 画面では「アチーブメント」と呼ぶ。API・DB・ID は今までどおり `trophies` / `trophy` のまま（ゲーム側の変更を要らなくするため）

### 2.2 レアリティは原作の値をそのまま出す

- レアリティはマイクリの id の千の位で決まる（1 Common・2 Uncommon・3 Rare・4 Epic・5 Legendary）。資産リポジトリで、4 桁の id を持つヒーロー 201・エクステンション 956 に例外がないことを確かめた（2026-10-18）。`platform/trophies.js` の `rarityOf()` がこれを使う
- **こちらでレアリティを書き換えない**。難しさとレアリティを合わせたいときは、**そのレアリティのヒーロー／エクステンションを選び直す**（名前も、そのスキル名に合わせて変わる。SPEC-001 D9）
- 図鑑に出ない絵は特別な扱い：エクステンションの Rep 版は `Replica`、ヒーローの MCHウォーリアーなどは `Special`。アチーブメントには使わない（段階 2 で「雪だるま」を張遼に置き換え、雪だるまは持っている人の「以前の絵」に）

### 2.3 難しさとレアリティの目安（段階 2 で全件に当てはめる）

**ヒーロー**

| レアリティ | 目安 | 例 |
|---|---|---|
| Common | 1 サイクル目で届く、いちばん最初の節目（30 分以内） | Survivor 最初のステージ、Fortress レベル 01 |
| Uncommon | 序盤の節目（〜1 時間） | Tactics 第 1 章、Factory 工房 Lv.2 |
| Rare | 中盤の節目・2 タイトル以上で節目 | Fortress レベル 05、横断「4 タイトル」 |
| Epic | **ゲームクリア** | 各タイトルのクリア |
| Legendary | やり込み（タイトル内でいちばん難しいもの）・タイトル横断の大目標 | Factory 3 年以内、全タイトルクリア、**エクステンションをすべて集める** |

- Common のヒーローは図鑑に 10 体（オリジナル 8・コラボ 2）。オリジナル 8 体を、8 タイトルの最初の節目にちょうど 1 体ずつ当てた

**エクステンション**（すべて Epic 以上。作者の決定 2026-10-18）

| レアリティ | 目安 | 例 |
|---|---|---|
| Epic | 来訪・初めての〇〇・共通基盤の機能 | 各タイトルを遊ぶ（ゲームで最初に操作したとき）、初めてボスを倒す、ログインする、アイコンを変える |
| Legendary | 通算の数・やや大きい目標・横断 | クラフト 50 回、敵 1,000 体、RTA を完走する、すべてのタイトルを遊ぶ |

### 2.4 真のゲームクリア

- **ヒーロー名鑑のすべてを持っている** と、アチーブメントの画面に「ヒーロー名鑑 完成 — 真のゲームクリア」と達成日（最後の 1 枚の日）を出す（段階 1 で画面だけ作った）
- 名鑑には「エクステンションをすべて集める」ヒーローが入るので、真のクリアにはエクステンションも全部要る
- 名鑑の最後の 1 枚（No.100 `cross.book99`）は「ほかの 99 枚をすべて埋める」。真のゲームクリアの瞬間に手に入る
- 今のタイトルで 100 枚（作者の決定）。タイトルが増えたら「第 2 章」として足す。**一度達成した真のクリアは記録として残す**（横断トロフィーと同じ考え。SPEC-001 9.2）。残し方は段階 5 で決める

## 3. 画面（段階 1。実装済み）

### 3.1 入口

- ポータルの上部、`スコア` `RTA` の並びに **`アチーブメント`**（`/achievements/`）。マイページのトロフィーの欄からもリンクする
- 400px 以下の画面では、リンクを詰めて GitHub のアイコンを畳む（4 つが 1 行に入らないため。GitHub へは各作品の詳細から行ける）

### 3.2 一覧

- 見出し：紋章・「HALL OF HEROES」・アチーブメント・「ヒーロー名鑑をすべて埋めると、真のゲームクリア。」
- タブ 2 つ：**ヒーロー名鑑 `獲得 / 総数`**・**エクステンション `獲得 / 総数`**（`?tab=ext` で直接開ける。←→ で切り替え）
- 進み具合：大きな `獲得 / 総数`、金の帯、レアリティごとの `獲得/数`
- タイトルでしぼる（すべて・各タイトル `獲得/数`・タイトル横断）
- **棚**：レアリティごとに 1 段。上から Legendary → Epic → Rare → Uncommon → Common。段の見出しにレアリティの色の宝石と `獲得 / 数`、下に棚板
- **1 枚**：ヒーローは上がアーチの額縁、エクステンションは四角い台座。枠と光はレアリティの色（Common 銀・Uncommon 緑・Rare 青・Epic 紫・Legendary 金）。下の銘板に **レアリティ**・名前・タイトル
  - 獲得：ドット絵（`image-rendering: pixelated`）。Legendary は光が走る
  - 未獲得：**影絵** と「？？？」。条件は詳細で読める（何をすれば手に入るかが分かることを、隠すことより大事にする）
- 押すと詳細：大きな絵・レアリティの帯・名前・アチーブメント名・タイトル・条件・獲得日・名前の由来、**「<タイトル> を遊ぶ ↗」**（初めての人がそのまま遊びに行ける）、ログイン中は「アイコン図鑑」
- ヒーローの額縁の上に名鑑の番号（`No.001`）
- 動きは `prefers-reduced-motion` で止める。チャットは棚が横に広いので PC でも 💬 の窓（`layout: 'float'`）

### 3.4 ログイン（作者の決定 2026-10-18）

- **アチーブメントの画面は Google ログインが要る**。未ログインでは「LOCKED — アチーブメントは、ログインすると見られます」と、この端末に貯まっている数、「Google でログイン」だけを出す
- 記録はこれまでどおり未ログインでも仮アカウントに貯まり、ログインでまとまる（SPEC-001 4.6）。マインの案内（4 章）はログインしなくても最後まで聞ける
- マイページのトロフィーの欄は「アチーブメント」に改め、ヒーロー名鑑とエクステンションの数とこの画面へのリンクだけにした（一覧は二重に持たない）

### 3.3 API

- `GET /api/trophies` の各トロフィーに `kind`（`hero` / `ext`）・`rarity`・`no`（名鑑の番号）・`formerAvatars` を足し、`gameUrls`（タイトル → URL）を足す。今までの欄は変えない
- `POST /api/trophies/visit { game }`：来訪（5 章）。`POST /api/trophies/welcome`：マインの話を聞いた（ポータルから）
- `POST /api/trophies/unlock` の返事に `firstHero`（そのアカウントの最初のヒーロー。4.2）
- `POST /api/me/avatar`・RTA の区切りの返事に `unlocked`（アイコン・RTA のアチーブメント）。SDK 1.10.0 が通知を出す

## 4. マインの案内（段階 4。実装済み：`js/guide.js`・SDK 1.10.0 の `showMineCall`）

説明は 3 回に分け、**遊ぶ前には「何を遊ぶか」だけ** を言う。ヒーローの話は、1 回遊んで節目のヒーローを手に入れたあとに初めてする。どの段階も閉じられ、強制しない。

### 4.1 初めて bearko.games に来たとき（ポータル）

条件：この端末で案内を見ていない、かつヒーローのアチーブメントを 1 つも持っていない。一覧の上にマインの吹き出し（ダイアログ。Esc・閉じるで消える）。

> マイン「ようこそ、bearko.games へ！ ここはマイクリのヒーローたちが活躍するゲームの集まりよ。
> まずは、すぐに遊べるこの 3 つから選んでみて！」
>
> - **Survivor** — 逃げて倒して強くなる。1 ステージ 5 分
> - **Fortress** — ヒーローを並べて幻獣から守る
> - **Workshop** — エクステンションを作って売るお店
>
> 〔あとで〕

- 3 つは作者の指定。所要時間は各タイトルの実測で書く（段階 4 で測る）
- Workshop は最初の節目（30 日目）まで長い（最初の 1 周が 2.5〜3.5 時間。README）。最初の節目を早めるかは 7 章 Q5

### 4.2 最初のヒーローを手に入れたとき（各ゲームの中・SDK）

条件：そのアカウントで **最初のヒーローのアチーブメント** を獲得した（API の返事に `firstHero: true` を足す）。SDK の獲得の通知に、マインを 1 行添える。押すと bearko.games へ。遊びは止めない。

> マイン「情熱的なプレイ、見てたよ！ bearko.games で待ってるね」〔会いに行く ↗〕

- `init({ ui: false })` で通知を消しているゲームは、`onTrophy` の 2 つ目の引数で `firstHero` を受けて、自分の画面で出せるようにする

### 4.3 bearko.games に戻ってきたとき（ポータル → アチーブメント）

条件：ヒーローのアチーブメントを 1 つ以上持ち、この端末でまだ聞いていない。3〜4 回のタップで進む短い会話にし、最後にアチーブメントの画面へ移って **手に入れたヒーローの額縁を光らせる**。

1. （きらきら）「君のプレイ、見てたよ！ とっても情熱的だった！」
2. （泣き）「ここにいるのは MyCryptoHeroes で活躍したヒーローたち。2026 年 9 月のサービス終了で、みんな散り散りになっちゃったの……」
3. （指し棒）「でも研究して分かったの。ヒーローは **ゲームを遊ぶ情熱** に引き寄せられるって！ だから呼び戻すために、マイクリのゲームをたくさん作ったわ。……ヒーローが多すぎて、1 本じゃ収まらなかったけど（横目）」
4. （両手を上げて）「ほら、君の情熱で〇〇が戻ってきてる！ 一緒にヒーロー名鑑を埋めて、みんなを呼び戻して！ お願い！」→ アチーブメントの画面

- 絵は資産リポジトリの `navi_ain_*`（`08_sparkle`・`09_cry`・`00_pointer_up`・`01_arms_crossed`・`02_both_arms_up`）
- 聞き終えたら、エクステンションのアチーブメント「マインの話を聞く」（`cross.welcome`・流星のホーキ）を渡す（記念の 1 枚。`POST /api/trophies/welcome`）
- どこまで聞いたかは **ポータルの localStorage**（`bg.guide`）に置く。端末が変わるともう一度出るが、それでよい（サーバーに持たせると、未ログインの初来訪で仮アカウントを作ることになる）

## 5. データと移行（段階 2。実装済み）

- 一覧は [ACHIEVEMENT_CATALOG.md](../ACHIEVEMENT_CATALOG.md)（`node tools/achievements.mjs table` で作る）。名前・絵の名前・レアリティが資産リポジトリと合っているかは `node tools/achievements.mjs check ../mycryptoheroes` で確かめる
- ヒーローには **`no`（名鑑の番号 1〜100。変えない・使い回さない）**。並びはタイトルごとに易しい順、最後が横断
- **今の 30 個はすべてヒーローになった**（ID はそのまま。SPEC-001 9.2）。節目なのにエクステンションだった 9 個と、難しさとレアリティが合わなかったもの（例：Tactics のクリアは織田信長 Legendary → 武田信玄 Epic。織田信長は Red Dragon のクリアへ）は、絵と名前を選び直した
- 選び直す前の絵は **`formerAvatars`** に残す。そのアチーブメントを持っている人は、前の絵もアイコンに使える（アイコン図鑑の「以前の絵」。持っている人にだけ出す）。アイコンに選んでいた人の絵も変わらない
- 移行（`migrations/0008_achievements.sql`）：
  - そのタイトルのトロフィーを持っている人に、そのタイトルの来訪（`<タイトル>.visit`）を渡す
  - 前の絵を新しいエクステンションのアチーブメントに移し、条件が前の条件に含まれるもの：`deckbattle.area1`（大西部のブーツ）→ `deckbattle.firstwin`「初めてバトルに勝つ」、`cross.two`（ダブルにゃんバーガー）→ `cross.visit2`「2 タイトルを遊ぶ」
  - 横断のヒーロー（名鑑 10 枚など）は、次に何かを獲得したときに判定し直される
- **来訪**は、SDK 1.10.0 がゲームで最初の操作（同時接続数の「操作あり」と同じ合図。SPEC-007）を受けたときに 1 回送る。ページを開いただけでは送らない（作者の決定）。止めるのは `init({ presence: false })`
- **共通基盤が渡すもの**（`judge`）：ログイン（`/api/auth/google`）・アイコン（`/api/me/avatar`）・チャット（`/api/me/trophies` を見たときに部屋に発言があれば）・RTA の完走（参考記録は除く）・タイトルをまたぐ RTA の完走・マインの話（`/api/trophies/welcome`）
- **横断の判定**（`crossTrophiesFor`）：ヒーローを呼び戻したタイトルの数（2・4・8）、クリアしたタイトルの数（2・4・全部）、名鑑の枚数（10・30・60・99）、すべてのエクステンション、遊んだタイトルの数（2・全部）。新しく得たものも数えに入れ、増えなくなるまで回す

## 5.2 名鑑の章（段階 5）

- ヒーローに `chapter`（省くと第 1 章）。いまの 100 枚はすべて第 1 章
- タイトルが増えたら、足すヒーローを `chapter: 2` にし、その章の名鑑の枚数（`book`）と最後の 1 枚（`trueClear: true`）を足して **第 2 章** とする。番号 `no` は 101 から続ける
- 名鑑の枚数はその章のヒーローだけを数える（`crossTrophiesFor`）。**第 1 章の真のゲームクリア（`cross.book99`）は、第 2 章が増えても消えない**（記録として残る）
- 画面：章が 2 つ以上になると、しぼりこみに「第 1 章」「第 2 章」が出る。完成の帯は「第 N 章 完成 — 真のゲームクリア」と、最後の 1 枚の日付
- API：`GET /api/trophies` に `chapter`（ヒーローだけ）と `trueClear`

## 6. 仕上げ（段階 5。TCG とのつなぎは別）

### 6.1 真のゲームクリアの演出

- アチーブメントの画面で、その章の最後の 1 枚を持っていれば「TRUE GAME CLEAR — ヒーロー名鑑 第 N 章 完成」の窓を 1 回だけ出す（この端末の localStorage `bg.ach.cleared.<ID>`）。その章のヒーロー全員が流れる行進、マイン（両手を上げる）の「みんな戻ってきた……！ これが真のゲームクリアよ」、達成日、「名鑑を共有」
- ゲームの中（SDK）でも、最後の 1 枚の通知は金色で「真のゲームクリア！ ヒーロー名鑑 完成」と「名鑑を見る ↗」（15 秒）

### 6.2 額縁へ飾る演出

- アチーブメントの画面を開いたとき、前に見たときから増えたものは、上から額縁に収まる動き（0.9 秒・光ってから絵が出る）と **NEW** の札
- 見出しの下に「前に見たときから、ヒーロー n 人・エクステンション m 個 が飾られました」
- 前に見た一覧は、この端末の localStorage（`bg.ach.seen.<アカウント>`）。初めて開いたときは何も「新しい」にしない。`prefers-reduced-motion` では動かさない

### 6.3 名鑑の共有

- 進み具合の下の「名鑑を共有」で、1200×630 の画像をその場でキャンバスに描く（ヒーロー名鑑 n / 100・エクステンションの数・帯・持っているヒーロー（貴重な順に 30 人まで）・真のゲームクリアの印）
- 「共有…」（Web Share でファイルを渡せる端末だけ）・「X に投稿」（文言とリンク `https://bearko.games/achievements/`）・「画像を保存」
- 人ごとの公開ページやサーバーで作る画像は作らない（会員番号を外に出さない・費用を増やさない）。`/achievements/` には OGP を付けた

## 7. 非ゴール

- アチーブメントで報酬（ゲーム内の通貨・強さ）を配ること。手に入るのはアイコン（と、予定の TCG のカード）だけ
- ガチャ・抽選でアチーブメントを配ること
- 未ログインの来訪だけで仮アカウントを作ること
