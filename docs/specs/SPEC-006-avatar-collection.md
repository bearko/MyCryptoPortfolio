## 1. 背景（作者の依頼 2026-10-18）

- アイコンの既定を **MCHウォーリアー** にする。**MCHウォーリアー・タクティシャン・アーティスト** は最初から選べる
- ほかのアイコンは **トロフィーで解放** する。**トロフィーの名前のスキルを持つヒーロー／エクステンション** が手に入る
- 選ぶ窓では **未獲得のアイコンもグレーで出し**、獲得条件（タイトルとトロフィー）を読めるようにする
- **全部でいくつあるか**（≒トロフィーの数）を出し、「アイコン図鑑を埋める」遊びにする

SPEC-005 1.1 では、図鑑に出るヒーロー 209・エクステンション 956 のどれでも選べた。これを置き換える。

## 2. 仕様

### 2.1 図鑑の中身

| まとまり | 数 | 解放 |
|---|---|---|
| 最初から | 3 | `hero:10001` MCHウォーリアー（既定）・`hero:10002` MCHタクティシャン・`hero:10003` MCHアーティスト |
| トロフィー | トロフィーと同じ数（いま 30） | そのトロフィーを持っている |

- トロフィーの名前はもともと MCH のスキル名から付けている（`nameFrom`）。そのスキルを持つヒーロー／エクステンションを `platform/trophies.js` の各トロフィーに **`avatar`（id）と `avatarName`（名前）** として書く（資産リポジトリの `passive.name` / `active_skill.name` で照らし合わせた）
  - 例外：「スノーフォール」を持つ雪だるまは図鑑に出ない Rep 版だけ。Rep F（`ext:11126`）は白黒の絵で未獲得の灰色と見分けがつかないので、色のある Rep E（`ext:12126`。スキル名は同じ「スノーフォール」）を使う
- **トロフィーを足すときは `avatar` も必ず付ける**（テストが、全トロフィーにあること・重ならないことを見る）。全体の数は `3 + トロフィーの数` で自動で増える
- 何も選んでいない人（`users.avatar` が NULL）の絵は MCHウォーリアー。D1 の列はそのまま（既定の絵を NULL で表す）

### 2.2 API

- `GET /api/trophies` の各トロフィーに `avatar` / `avatarName` を足し、`avatars: { default, starters: [{id, name}], total }` を足す
- `POST /api/me/avatar { id }` は、**最初からの 3 体か、持っているトロフィーのアイコン** だけを受ける。ほかは **403 `locked`**。`null`（既定に戻す）は今までどおり
- 仮アカウント（未ログイン）は今までどおり決められない（401）。図鑑は見られる（`/api/me/trophies` は仮アカウントのものも返す）

### 2.3 SDK 1.8.0：アイコン図鑑の窓

- `openAvatarPicker()` の窓を「アイコン図鑑」にする（呼び方は変えない。各タイトルの入口はそのまま）
- 上に **`獲得数 / 全体`** と進み具合の帯。まとまりごと（最初から → タイトル → タイトル横断）に `獲得 / 数`
- 未獲得はグレー＋🔒。札の下にはトロフィーの名前
- 押すと下の欄に詳しく：絵・名前・**獲得条件「<タイトル> のトロフィー「<名前>」 — <説明>」**、または獲得済みなら「獲得：…」。ボタン「これにする」（使用中・未獲得では押せない）
- `avatarUrl(null)` は MCHウォーリアーの絵を返す（チャット・ポータルの上部の流れ・マイページの絵がすべてこれになる）
- トロフィー獲得の通知に「アイコン『<名前>』が使えるようになりました」を足す
- タブと名前の検索、`assets/avatars.json`・`tools/make-avatars.mjs` はやめる（33 件なので要らない）

## 3. 移行

- 本番の D1 で、アイコンを決めた人は 0 人だった（2026-10-18 に確かめた）。データの移行は無い

## 4. 非ゴール

- トロフィーを持たないアイコンの解放（ショップ・抽選など）
- 1 つのトロフィーで複数のアイコン
