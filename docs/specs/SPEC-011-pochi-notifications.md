## 1. 背景（作者の依頼 2026-11-27）

- ポチゲーブラウザのプッシュ通知で、MyCryptoFootball の公開を知らせたい（用途は「サービス連絡」。ゲームの中の新作の告知で、ポチゲーの掲載規約には当たらないと作者が確認した）
- ポチゲーの通知は、ポチゲーに登録した **ゲームごと** の設定。bearko.games は **1 つのゲーム**（ゲームキー `mycryptgames`、URL `https://bearko.games`）として登録しているので、どのタイトルの知らせもこの 1 つで送る。タイトルや種類はポチゲーの「通知チャンネル」で分ける
- 届くのは、ポチゲーブラウザでこのゲーム（とそのチャンネル）の通知をオンにした端末だけ。購読している端末がいなければだれにも届かない。新しく足したチャンネルは全員オフから始まる

## 2. ポチゲーの通知仕様 v1（要点）

| 項目 | 決まり |
|---|---|
| イベントフィード | ログイン不要の GET で `{ spec_version: 1, events: [...] }` を返す。登録した URL と **同じ origin**（`https://bearko.games`）の HTTPS。256 KiB 以内。先頭 50 件まで読む（新しい順） |
| 出来事 | `id`（100 文字以内。同じ出来事は同じ ID）・`channel`（登録した公開中のチャンネル）・`title`（60 文字）・`body`（160 文字。HTML・`<` `>`・改行・制御文字は不可）・`url`（500 文字。押したときの行き先。同じ origin）・`published_at`（タイムゾーン付き ISO 8601。実際の発生時刻）・`expires_at`（省略可） |
| 配る時機 | ハブがフィードを取りに来た時点で、15 分より古いもの・2 分より先のものは配らない。定期的には取りに来ない |
| 共通ハブ | `POST https://games-alchemist.com/api/portal/notifications/hub/`、`Authorization: Bearer <ゲームの API キー>`（同時接続数と同じ）、本文 `{ "game_key": "mycryptgames" }`。受け付けは 202（`queued: true` なら取りに来る、`false` は購読している端末がいない）。401 キー違い・403 停止中・非掲載・規約未同意・429 間隔が短い（`Retry-After`） |
| 上限 | ゲームごとに 60 秒以上あける。同じチャンネルは 60 秒以上、直近 1 時間でチャンネルごと 4 件・ゲーム全体 10 件、直近 24 時間でゲーム全体 30 件 |

## 3. 作ったもの

### 3.1 イベントフィード

- **URL：`https://bearko.games/api/game-events/`**（ポチゲーの編集ページの「イベントフィード URL」に入れる）
- 表 `pochi_events` の新しい順に 20 件。`Content-Type: application/json`、`Cache-Control: no-store`
- 中身は管理画面から作ったものだけ（公開してよい告知だけ）

### 3.2 管理画面の「ポチゲー通知」タブ

- チャンネル ID（既定 `new_title`）・タイトル・本文・行き先（既定 `https://bearko.games/`）を入れて「フィードに載せて、ポチゲーに知らせる」
  1. 中身を確かめる（チャンネル ID は英小文字・数字・`_` の 40 文字まで、文字数、改行と `<` `>` が無いこと、行き先が `https://bearko.games` の中）
  2. いまの時刻を `published_at` にして表に入れる。ID は `<チャンネル>_<日本時間の YYYYMMDD_HHMMSS>`
  3. すぐに共通ハブへ知らせ、返事（HTTP の状態・`queued`）を記録して画面に出す
- 「もう一度ハブに知らせる」：いちばん新しい出来事について、ハブへ知らせ直す（前回が 429・通信の失敗だったとき。フィードは変えない。15 分を過ぎると配られない）
- ハブへ知らせる間隔は 60 秒以上（こちらでも止める）
- 送った通知の一覧（20 件）と、それぞれのハブの返事
- 行き先は `https://bearko.games` の中だけ（各タイトルのサブドメインは別の origin なので書けない）。タイトルの紹介はポータルの詳細（例 `https://bearko.games/#football`）

### 3.3 鍵

- API キーは同時接続数と同じ Worker のシークレット `POCHI_API_KEY`。サーバーの中だけで使い、フィード・画面・ログには出さない
- 共通ハブの URL は `wrangler.jsonc` の vars `POCHI_HUB`（公開してよい値）
- キーが無い環境（プレビュー）では送れない（`503 no_key`）。フィードは読める

## 4. 作者の操作（ポチゲーの編集ページ）

1. 掲載規約に同意する
2. 通知チャンネルを足す：ID `new_title`・表示名「新作・アップデート」・説明「新しいタイトルの公開や大きな更新」・用途「サービス連絡」・公開
3. イベントフィード URL に `https://bearko.games/api/game-events/` を入れる
4. 「このゲームの通知を提供する」をオンにして「通知設定を保存」
5. 自分のポチゲーブラウザで、このゲームと `new_title` の通知をオンにしておく（確かめ用）
6. 管理画面の「ポチゲー通知」タブから送る

## 5. 非ゴール

- タイトルごとにポチゲーへ別々に登録すること（bearko.games は 1 つのゲームとして登録している）
- 出来事を自動で作ること（ゲームの中の出来事から自動で知らせるのは、必要になってから）
- 送った出来事の取り消し（フィードから外しても、配られたものは戻らない）

## 6. 確かめ方

- `platform/test/pochi.test.mjs`：中身の確かめ・時刻と ID・ハブへの知らせ（Authorization と本文）・管理画面から送るとフィードに載ってハブへ知らせる・60 秒の間隔・管理者だけ・`queued: false` の記録・キーが無いと送れない・フィードと画面に API キーが出ない
- `POCHI_FAKE=none ADMIN_SUBS=admin node tools/e2e/server.mjs` で、偽の共通ハブにつないで管理画面から送る
