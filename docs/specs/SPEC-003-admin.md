# SPEC-003 管理画面（点数の分布・RTA の記録・締め出し）

| 項目 | 内容 |
|---|---|
| 状態 | Accepted（2026-10-17） |

| 置き場所 | 画面 `admin/index.html`（`bearko.games/admin/`）、API `platform/admin.js`、表 `migrations/0005_bans.sql` |

## 1. 目的

- **係数の見直しの材料**：タイトルごとの総合スコアの分布（件数・中央値・上位 10%）を見る（SPEC-001 8.3・8.4。分布は見るだけで、計算式には入れない）
- **不正への備え**：RTA の記録の一覧を見て、おかしな記録を消す。同じ人が繰り返すなら締め出す（SPEC-001 6.5）

## 2. 決まっていること（作者の決定 2026-10-17）

| # | 論点 | 決定 |
|---|---|---|
| A1 | 管理者の見分け方 | **Google の会員番号（`sub`）の一覧**。ポータルにふだんどおり Google でログインした人のうち、会員番号が一覧にある人を管理者にする（管理トークンは使わない） |
| A2 | 締め出したプレイヤーの扱い | **ランキングから隠し、新しい記録を受け付けない**。ログインと、自分の記録を見ることはできる。解除すれば元に戻る（締め出しでは記録を消さない） |

## 3. 管理者の設定

- 一覧は Worker の **シークレット `ADMIN_SUBS`**（会員番号をカンマか空白で区切る）。リポジトリには書かない（個人を指す値のため）
  - Cloudflare のダッシュボード：Worker（`mycryptoportfolio`）→ Settings → Variables and Secrets → Add → Type「Secret」、名前 `ADMIN_SUBS`
  - `wrangler.jsonc` の `vars` に書くと、デプロイのたびにダッシュボードの値が上書きされるので、シークレットにする
- 自分の会員番号は、ログインして `bearko.games/admin/` を開くと「あなたの会員番号」として出る（管理者でなくても、本人の番号だけは見える）
- `ADMIN_SUBS` が空なら、誰も管理者にならない（管理画面は「管理者ではありません」を出すだけ）

## 4. 画面（`bearko.games/admin/`）

検索エンジンに載せない（`noindex`）。ポータルのどこからもリンクしない。

### 4.1 総合スコア

タイトルごとに 1 行：

| 列 | 中身 |
|---|---|
| 件数 | 自己ベスト（`title_scores`）を持つアカウントの数。内訳としてログインした人の数も出す |
| 中央値 | 自己ベストの中央値（偶数件なら真ん中 2 つの平均） |
| 上位 10% | 上から数えて 10% の位置の点（この点以上が上位 10%。件数 × 0.1 を切り上げた順位の点） |
| 最高 | 一番高い点 |
| 計算式の版 | いま使っている版（`tactics.v2` など） |

- 母集団は **締め出していない全アカウント**（仮アカウントも含む。ランキングに出ない人の成績も、係数を見直す材料になるため）
- 行を開くと、そのタイトルの上位 10 件（名前・点・節目の点・成績の点・ログインか仮か・日付）が出る。おかしな点があれば、そこから記録の削除・締め出しができる
- 記録の削除（総合スコア）：その人のそのタイトルの自己ベストと、保存している生の成績を消す。積み上げのタイトルは、次に遊んだときに今の値でまた入る（繰り返すなら締め出す）

### 4.2 RTA の記録

- レギュレーションを選び（「すべて」も可）、**完了した記録**を新しい順（または速い順）に 100 件まで出す
- 1 件ごとに：名前・ログインか仮か・公式タイム・IGT・参考記録か・一番長かった無操作・区切りごとの経過・完了した日時・締め出し中か
- 記録の削除：その計測と区切りの記録を消す。ランキングは自己ベストの集計なので、次に速い記録が繰り上がる

### 4.3 プレイヤー

- 名前か ID で探す（20 件まで）。会員番号は出さない（本人の画面以外では）
- 締め出し：理由（200 文字まで・任意）を付けて締め出す。締め出し中の一覧から解除できる

## 5. 締め出し（A2）

表 `bans`（`migrations/0005_bans.sql`）：

| 列 | 中身 |
|---|---|
| `user_id` | 締め出したアカウント（主キー） |
| `google_sub` | そのアカウントの会員番号（仮アカウントは空） |
| `reason` | 理由（任意） |
| `banned_at` | 締め出した時刻 |

- **隠す**：総合ランキング（総合・タイトル別）と RTA ランキングの集計から外す。自分の順位の計算（「あなたは n 位」）も、外した母集団で数える
- **受け付けない**：成績の送信・トロフィーの獲得・RTA の開始と区切り・「操作あり」を `403 { error: 'banned' }` で返す。SDK は失敗を `{ ok: false }` で返すだけなので、ゲームは止まらない（SPEC-001 5 章）
- 本人には、マイページに「このアカウントは記録の受け付けを止めています」と出す（`GET /api/me` が `banned: true` を返す）
- **退会しても締め出しは残す**：退会で行を消すと、退会してログインし直すだけで抜けられるため。退会したあとも `bans` の行（会員番号と理由）だけは残り、同じ会員番号で新しく作ったアカウントにも、ログインのときに締め出しを付け直す（SPEC-001 4.4 の「退会で全記録を消す」の例外。残すのは会員番号と理由だけ）
- 仮アカウントを締め出したあと、その端末でログインすると、本アカウントも締め出す（同じ人とみなす）
- 毎日の掃除で、消えた仮アカウントの締め出しの行を消す（会員番号がないので、残しても付け直せない）
- 解除：その会員番号の行をすべて消す（退会前のアカウントの分も）

## 6. API

すべて `/api/admin/*`。ログインしていなければ `401 { error: 'login' }`、管理者でなければ `403 { error: 'admin' }`（`/api/admin/me` を除く）。

| API | 用途 |
|---|---|
| `GET /api/admin/me` | `{ admin, user, sub }`。`sub` はログインしている本人の会員番号（3 章の設定用） |
| `GET /api/admin/scores` | タイトルごとの分布と上位 10 件（4.1） |
| `POST /api/admin/score/delete { userId, game }` | 総合スコアの記録を消す |
| `GET /api/admin/rta?regulation=&order=recent\|time` | RTA の完了した記録（4.2） |
| `POST /api/admin/rta/delete { runId }` | RTA の記録を消す |
| `GET /api/admin/users?q=` | プレイヤーを探す |
| `GET /api/admin/bans` | 締め出し中の一覧 |
| `POST /api/admin/ban { userId, reason }` | 締め出す |
| `POST /api/admin/unban { userId }` | 解除する |

- 管理の API は **`https://bearko.games` の画面からだけ** 受ける（Origin が付いていて、それがゲームのサブドメインなら 403）。ゲームのページから管理の情報を読めないようにするため
- 書き込み（POST）は、ほかの API と同じく Origin を確かめる（CSRF 対策）
- 管理者の操作は Worker のログ（`console.log`）に残す（誰が・何を・どの記録に）

## 7. データ量

管理画面を開くと、総合スコアの分布のために `title_scores` を全件読む（いまは数十行。1 万人になっても 1 回 10 万行未満で、1 日 500 万行の無料枠に対して作者が数回開く程度なら問題ない）。重くなったらタイトルごとに分けて読む。

## 8. 確かめ方

- `npm test`：管理者の判定・分布の計算・削除・締め出し（隠す・受け付けない・退会しても残る・解除）
- ローカル：`ADMIN_SUBS=admin node tools/e2e/server.mjs` で開き、`/admin/` に偽の Google ログイン（`ok:admin`）で入る
